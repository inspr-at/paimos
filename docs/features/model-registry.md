# Model registry card

Settings › Models ends with the **Model registry**: every model PAIMOS can run, by provider. It replaces the Catalog freshness fold of the old Models page; the old `#model-refresh` and Agents `#models` links open it.

## Lines, versions and routes (AEON-1163)

The registry groups by provider (OpenAI, Anthropic, xAI, Google, Cursor, Local, then models of an unknown provider) and shows **one row per line**: "Claude Opus" with its current version "5.5" beside it. A line's current version is its newest that runs and is not old. A newer version that is still off ("New · off until used") keeps a row of its own, so it can be paused or removed. Older versions fold under their line, and the row says "+2 older". A registry of 36 harness and model ids, modelled on the live one, shows as 18 rows; a line above the list counts the models, routes and lines.

A version runs through one or more **routes**: Opus 5.5 through Claude Code, Cursor and pi is one model, one row, with three routes. Lines follow the server's provider line (`modelsLine`), so Anthropic and OpenAI models are one line whichever harness runs them. Cursor's per-level Grok ids (`grok-4.7-low` … `grok-4.7-xhigh`) are one route, shown as `grok-4.7-‹level›` with "4 ids in Cursor, one per level". An alias such as Claude Code's `opus` is one more route of the current version.

Every model has one name everywhere: the picker, the registry rows, the outdated tray and the review sheet all use `fullName` ("Opus 5.5", "GPT-6.1 Sol"). A concrete route names the version; an alias and Cursor's raw display ids never do.

Rows are folded by default. A row shows its line and version, where the model came from, its tags (**New** and "off until used", **Retiring 31 Oct**, "+N older"), one line with the pause (**Paused until 14 Oct**) first and then the routes or the harness with the note, and the levels of its first route. That line never wraps, so pausing never adds a line above a row's actions; the routes and the note it shortens are in the fold in full. Opening a row grows its fold below it, so nothing above it moves. The fold shows:

- each route: harness (with "via OpenRouter" or "via Local" for pi and OpenCode), the id the harness is given, the route's own native levels (Gemini 2.5's token budgets say "tokens" once), and where the route came from;
- the facts: provider, lifecycle (Active, Preview, Retiring 31 Oct, Deprecated, Superseded) and the note, each with its source, or "unknown" when nobody reported it; "was 6, taken on 3 Oct" when auto-update took a newer version on;
- the older versions, each with its routes, why it is old, its source and its levels.

Sources are **Shipped**, **From provider**, **From harness** and **Added by hand**, from the profile's origin. Older servers only tell auto from manual; "auto" cannot say who reported a model, so it shows "unknown" and nothing says "Auto-discovered" any more.

## Who may do what

Everyone who can read models sees the registry. People with `models.manage` act on it; agent keys never get controls.

- **Auto-update** switches `auto_add_profiles`, the New model versions rule of the account matrix (AEON-1054). It is the rule's only writer (AEON-1148). The whole settings object is written back with the matrix revision; a competing rule change answers 409 and nothing is saved. A failed save puts the switch back and says so in the strip.
- **Check now** needs `models.refresh`. It skips the refresh interval, and the server holds a five-minute cooldown. The button keeps one size through *Check now*, *Checking…* and *Checked · again in 5 min*; a 429 shows the wait the server names. With vendor model lists switched off, the message says nothing new could be found rather than "up to date". A check whose sources are stale or limited says discovery was incomplete or partial. A newer version of a line already in use is "taken on" only when the check names the accepted model.
- **How new models are found** is a quiet fold under the strip. It holds what the old Model catalog form did (AEON-1138): models agents report, vendor model lists, the check interval, the vendor keys those lists use (an account's key is sent once, never shown again, and can be removed), and models a harness reported that wait for a person (**Accept** enables one). Its writes send the settings with `auto_add_profiles` as the server holds it, so they never change auto-update and never need the matrix revision. A failed save puts the control back and says so.
- **Add model** opens the form under the strip. pi through OpenRouter takes any OpenRouter slug (`qwen/qwen3-coder` is stored as `openrouter/qwen/qwen3-coder`). One level is one `POST /api/models`; several levels are registered in order with one `PUT /api/models/lines/{harness}/{model}` afterwards. If that second write fails, the route exists with its first level and the form says so; nothing is reported as saved.
- **Edit {harness} route** appears only for a route added by hand; provider and harness facts are read-only. It opens under the line and creates a new version through the same `PUT`: name, note, levels, route and slug can change. The save sends the registry revision together with the profiles from that same usage read, as one snapshot; a read belongs to the form that asked for it. A stale revision closes the form, reloads the list and keeps no draft. **Undo** writes the earlier values back at the revision that edit returned.
- **Remove…** removes the version the row shows, every level of every route. It first asks `GET /api/models/lines/{harness}/{model}/usage` once, with every profile it removes as a `profile` parameter, and says, in one sentence, every place the version is used and what takes over there. That one read excludes all of them, so a route that goes in the same step is never named as what takes over. Uses come from current storage: orders of every situation (First build, Fix rounds, Stuck and Review are named, "Review · Default"), rules not yet moved to Models and the row constraints they moved to; each use's fallback is resolved in its own situation, a review against the row's build pick without the version. A newer version of the same line that stays keeps a line reference, so that reference is no use. It cannot go ahead without the answer; a route that is gone since answers 409 and the question offers **Try again**. A partial removal says how many levels went; **Undo** restores them.
- **Pause…** pauses every route of the version: until tomorrow at 04:00, for a week, or until resumed, through `PUT /api/models/lines/{harness}/{model}/pause` (Cursor's Grok levels are covered by one call). **Resume now** appears while something is paused. The row says "Paused until 18 Oct", "Claude Code paused" or "Partly paused", and so does **Pause…** once every route is paused alike. Pause… keeps one box for every label it can show, so pausing, resuming and Undo never move it, **Remove…** or the row (AEON-541). When the routes are paused differently, each paused route is named below the actions ("Claude Code paused until resumed"), never above them. A refused route stops the rest and the toast says how many routes changed; **Undo** puts back exactly what each changed route had.

## Old versions (AEON-1164)

When registered versions have a newer successor that is registered too, a tray under the strip names the two successors that take over most uses and the count, for example "Opus 5.5 replaces Opus 5 · Gemini Pro 3 replaces Gemini Pro 2.5 · 4 old versions". On a phone, **Review…** sits on its own line under the sentence. With auto-update on, the uses have already moved, so the tray adds "nothing uses them", or "nothing you can see uses them" when other people's choices are hidden. The list comes from `GET /api/models/outdated` in pages of 50, read with the registry; when the pages read so far offer fewer than 50 versions that can move, the next page is read too, up to eleven pages, all at the first page's revision.

**Review…** opens a sheet over the page. It lists each old version with its successor, its routes, why it is old and where that fact came from, each with a box, all ticked. Below them is every use that moves, in words, with the level it moves at: "Opus 5 · xhigh → Opus 5.5 · xhigh", "Gemini Pro 2.5 · 32k budget → Gemini Pro 3 · high". The server sends both levels (`from_effort`, `to_effort` on each use, AEON-1163): the level the use runs the old version at, and the successor's nearest level, ties going up, which is the level the retirement then writes. Rules, locks and pauses carry no level. Nothing is written until **Remove N old versions**, which posts the ticked versions to `POST /api/models/outdated/retire` with the revision they were read with; every use moves and the old versions go in one step. The toast offers **Undo** for ten seconds. A stale preview removes nothing, says so, and the list is read again. When no answer comes back, the step may have happened: the toast says so and the list is read again. The page under the sheet never moves, focus stays inside it, and Esc closes it.

## Keyboard and stability

Esc leaves a field, then closes the form or the remove question and returns focus to the control that opened it; ⌘↵ (Ctrl+↵ elsewhere) saves from a field. The Pause… menu takes ↑ ↓, Home and End; Esc closes it. Folds, the remove question, the editor and the discovery settings all grow below the control that opened them (AEON-541).
