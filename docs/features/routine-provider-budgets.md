# Routine provider budget boundary

Automatic routine execution remains off. This boundary adds no launcher, new account authority, migration or release qualification. Ordinary runs without `routine_budget` retain their existing behavior. The current native adapters refuse budget-bearing routine work with `budget_enforcement_unavailable` before routing, claiming or starting a vendor process, including combined token and money mode.

A qualified adapter must enforce each request's maximum before any billable provider work. That includes input, reasoning/output, cache reads and writes, tools, retries, compaction and concurrent calls. The optional transport binds the held S09 actor envelope and remaining allowance to tenant, agent, account, model profile, daemon generation, exact runtime digest and immutable provider/model/USD price provenance. Money limits require known paid API billing. Subscription usage cannot satisfy a money budget or become invented paid dollars.

`RoutineBudgetAdapter` is a trusted implementation interface, not an advertised capability or cancellation promise. Its dedicated start path receives a `RoutineCallBudget`; every provider request goes through `Call`. Before the provider callback, the controller reserves the complete maximum through the authenticated `RoutineBudgetBroker` seam. The broker must persist a new dispatch intent and S09 subgrant under current authority; replayed or unresolved intents never permit another call. S11 owns authoritative transport issuance, final claim checks and wiring this broker. There is no `Remote` implementation or fallback to ordinary telemetry in this slice. A controlled fixture demonstrates the interface; no native adapter is claimed as qualified.

Token categories are disjoint and output includes reasoning. Upper-bound rates use integer micro-USD per million tokens, rounded upward per category, plus a qualified upper bound for all additional tool fees. Checked arithmetic and a locked sum of settled actual usage plus outstanding maxima bound parallel calls. Call duration is bounded separately within the recovery envelope. Actual paid charges come from provider evidence rather than calculated list prices. Complete, known, acknowledged receipts settle once; partial usage, provider reply loss or settlement acknowledgement loss retain the maximum. Reconciliation never re-dispatches. The first exhausted dimension closes later relevant actions; reconciliation cannot silently restart an exhausted actor.

The native Codex path sends `thread/start` and `turn/start` through app-server and receives usage notifications after work. It supplies no immutable per-provider-request token/fee allowance or admission hook. The [official app-server protocol](https://learn.chatgpt.com/docs/app-server) documents turn startup, interruption and `thread/tokenUsage/updated`; it does not establish the required spending boundary. The [ChatGPT plan preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) also exclude arbitrary Responses parameters and `max_output_tokens` on that route. These observations do not qualify a hard cap. Repository evidence is `internal/agentd/adapters.go` (`CodexAdapter.Start`) and `internal/agentd/codex_usage.go` (usage handling).

Claude's native bridge similarly checks token usage on `result` messages after the SDK has performed the turn (`claudeassets/bridge.mjs`, `observeUsage` and the result loop). Its managed tool restriction, `max_turns` and graceful cancellation do not establish a complete per-call token/money maximum. Both native routes remain refused until a stronger, separately approved boundary is implemented and qualified on the exact artifacts. No vendor code is rewritten and no model or account is substituted.
