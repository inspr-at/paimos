# Delivery after release publication

A running tagged PAIMOS AEON build supplies private Git evidence to the status autopilot. Every minute, starting at server startup, it checks Done work leaves in the AEON project of the configured GitHub App tenant and repository. Development builds, untagged candidates and other tenants/projects do not run this publication path. The release image becomes live only after the existing release/deployment approval flow; the worker neither publishes nor deploys anything.

The release-history generator embeds the complete commit delta between this tag and the previous published tag. GitHub-enriched builds require a verified previous publication; reservations are excluded. This private evidence includes merges and is independent of the bounded, non-merge display changelog. It adds no API fields or routes. The GitHub App tenant/repository binding must match the build repository; an absent binding disables this path.

The newest verified `delivery.merge_done` or `delivery_merge_audit` fact decides membership. A later follow-up outside the tag keeps the ticket Done. Before those facts existed, a key in the first-parent merge branch/PR title or squash subject can establish membership. Editable ticket fields and rNN labels do not establish it. For fallback key linkage without a verified merge fact, a Done episode begun after the tag stays Done. Verified merges can still deliver when merge-to-Done processing arrives late.

Workspace/server/project Off, Suggest, disabled publish, `no_release_needed`, classic imports, work parents and person checks retain their safeguards. Each bounded transaction takes the tenant/pairing/tree fence, locks its candidate batch, and rechecks an existing responsible person's current `nodes.write` permission before writing as System. No role or key is created. Failed reads/authorization abort the batch and are logged; they do not claim delivery. Publication events and comments name the release, calendar version and tag. Receipts survive restarts, repeated publication and Undo.

Delivered then participates in the existing daily acceptance rule using the workspace's live delay (one day on PPM, unchanged 30-day default elsewhere). Human checks, person objections/comments, acceptance Undo and `delivery_objection` prevent unattended acceptance. The daily cadence may defer a transition to the next pass after the configured interval has elapsed.

Only the current tagged release delta is automatic. Historical repair uses `node scripts/release-delivery-backfill.mjs --project <AEON project UUID>` after fetching current main and tags. The command reads through the existing CLI and GitHub authentication, writes only its local Markdown report, and rejects apply options. `--live <calendar version>=<RFC3339 instant>` adds explicit OPS/LEAD live evidence; without it, the running server's `live_since` provides a conservative bound. See [the captured inventory and OPS plan](../ops/aeon-1481-backfill.md). Historical acceptance is conditional on a final objection check. OPS performs any real backfill only after LEAD approval.
