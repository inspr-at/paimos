# Decision Desk on Agents

The Desk panel on Agents replaces the former Needs you queue. It groups held and ready decisions from the canonical server projection and opens their original source records in Decision Desk. The header Desk count uses that same projection; Sessions counts continue to filter the session list. Sign-ins, connection chores and ticket triage keep their own surfaces.

Questions, held action requests, approvals, pending doctrine changes and managed session tier requests retain their native identities, permissions and decision workflows. Existing key trim requests remain available. Opening the panel or a memo does not decide, backfill or notify anything. Decided history remains accessible, including exact approval links beyond the first list page.

A memo round keeps its membership while it is open. New arrivals belong to the next round. Failed or partial reads show retry and coverage feedback; a failed canonical read leaves the count unknown. Native history pagination keeps the canonical open order, and actions recheck the source identity before recording a result. Phone memos use a full-height sheet with pinned actions, while desktop controls stay above the content.

Small tablets up to 960px use the same full-height sheet and pinned actions so the toolbar stays visible. A decided question or handover retains its project link and colour when revisited. Open run approvals retain the canonical project's identity; approval history resolves ownership through the authorized run and work-order reads. Ticket-linked doctrine proposals use the same authorized project lookup in the Agents panel and the full Desk.

This cutover adds an approval detail read and projection metadata without changing stored records or adding a migration. Step-up and the separate phone redesign remain independent delivery items.

Every item names its project (AEON-1057). The memo lists Project first, linked to the project's page in a new tab; P does the same outside text fields, and browser shortcuts such as ⌘P keep working. The folder tab carries the project too. When the item shown before was in another project, the tab's project is filled and the memo says "Now in X. The item before was in Y."; the first item of a round never shows it, and jumping through the list counts as moving. The jump list has a project column, a dashed line where the project changes and a project count when the round spans several. Desk list rows, phone rows, Decided rows and the Agents panel show the project as well. Projects have no colour of their own, so each gets a stable hue from its key. A rule change takes its project from its ticket. Workspace-wide items (key trims, workspace approvals, rule changes without a ticket) show Workspace without a link. Phone push notifications stay content-free and name no project.
