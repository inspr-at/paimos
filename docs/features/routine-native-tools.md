# Routine native tool boundary

Routine builders receive a run-bound local MCP inventory: workspace read,
write, edit, glob, grep and the bounded terminal entry point. The daemon does
not expose its ordinary comment, status, criterion, evidence, approval, reply
or activity tools to that builder. Outward work, knowledge, evaluation, spend
and pipeline actions remain coordinator/broker operations with their existing
authorization and receipts. The local MCP credential cannot serve as an Aeon
API credential; the daemon's API key stays outside the adapter.

File mutations reject runtime configuration, hooks and the compiled guardrail
engine's protected paths before opening files. The existing descriptor-based
file tools reject symlinks, hard links and foreign workspace paths. This local
floor does not replace full broker policy or required different-family
evaluation when an artifact leaves the workspace.

Native routine startup requires an independently implemented
`RoutineToolAdapter` capability before an account probe or vendor process.
Workspace allocation, a server qualification record, prompt instructions and
manual managed controls cannot establish that capability. Codex remains
unqualified: the existing app-server integration cannot bind its immutable
inherited MCP/hooks ceiling. Its harmless verification capability remains
unsupported. No native adapter is qualified by this change and no other model
family is substituted.

The current macOS terminal fence confines network and foreign filesystem
access but permits repository code to write throughout its workspace. That
does not protect the routine's own runtime or gates. Routine terminal calls,
including tests and local commits, therefore return
`routine_tool_enforcement_unavailable` before toolchain probes or execution;
push and arbitrary shell commands are rejected by the existing allowlist.
Ordinary manual managed runs retain their existing tools and terminal behavior.

Automatic execution remains off. Enabling a native routine route requires a
qualified external process/file/network boundary, exact native model and
selected-account evidence, successful local build/tool receipts and observed
owned exits through the coordinator/OPS native qualification slice. Synthetic
startup and MCP tests prove refusal and local proxy behavior; they do not prove
a successful native build or native sandbox escape resistance.
