# Routine budget holds

Routine execution remains off until the project's person-owned execution setting, exact-artifact qualification and routine consent are accepted. This slice supplies an internal transaction broker; it installs no scheduler, provider adapter or automatic launcher.

A routine run has one frozen `off`, `tokens`, `money` or `both` balance. Tokens and actual paid micro-USD use checked integer arithmetic. Combined mode refuses the first exhausted dimension. Subscription list-price comparisons never count as paid charges. Off removes the routine token/money ceilings while retaining owner permissions, account context, the single dial, daily/harness limits, quota reserve and the accepted subscription recovery envelope. No monthly tenant ceiling is added.

`routinebudget.Broker.ReserveTx` reserves an actor envelope for lead, evaluate, build, review or fix against the same run balance. An envelope holds both its maximum resources and its process slot. Every provider call consumes `SubgrantTx` within that envelope; settled call usage plus outstanding call maxima cannot exceed the parent. Subgrants do not create another ceiling or slot. A grant is unique by run, action, attempt and grant key; altered replay conflicts.

`SettleTx` accepts evidence only from the qualified adapter/reconciler, inside the authenticated final transaction. Root token and paid totals must reconcile exactly to settled call receipts. Complete usage and confirmed owned-process exit settle a root once, retain actual charges and release only the unused allowance. Partial/unknown usage, a lost reply, unknown exit or cancellation without exit retain the hold and slot. A demonstrably unused persisted intent can release without claiming process exit. Unknown receipt evidence is retained for reconciliation. Owner revocation closes new grants but never clears an uncertain hold.

Admission reuses the existing exact-account predicates. Mandatory numeric vendor room and native host load must be fresh under a server-owned `RoutineGateContract` bound to the accepted qualification and capability digest. The qualification supplies explicit maximum ages; absent evidence has no default or bootstrap exception. Ages can tighten the existing ten-minute account and one-minute host bounds. Paid API execution additionally requires a separately accepted exact-account context in that contract; ordinary subscription-only execution does not inherit API authority.

The caller uses a bounded `db.InTenant` transaction, enters tenant/tree/pairing fences before record rows, rolls back every error, and appends audit events after all resource writes. No network, provider or model call occurs in this transaction. `Broker.StartCheck` is the final-claim callback for the authenticated daemon; it repeats consent, qualification, exact account/host freshness and dial checks. Existing claim callers without this integration return `routine_start_check_unavailable` for bound routine work. S11 still owns daemon generation/capability and isolated workspace qualification; S10 owns enforcing each provider-call maximum. An envelope replay is a receipt, never launch authority.

Routine child/review/fix orders retain explicit run lineage. Internal `CreateInput.RoutineRunID` cannot be supplied through public HTTP JSON. `BindRoutineOrderTx` binds existing inert queue orders without creating budget or execution authority. Unbound descendants cannot reserve or claim. Installations with no qualified budget balance preserve ordinary work-order behavior.

Migration 1323 adds tenant- and routine-scope-protected balance, grant, settlement and order-binding tables. It changes no existing table or migration. These records are classified in the DSAR inventory. Integrated native and previous-binary compatibility qualification remain coordinator/OPS gates before activation.
