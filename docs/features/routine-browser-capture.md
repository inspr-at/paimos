# Routine browser capture

Saved routine assignments already distinguish `native_coding` from
`native_browser`, with `needs_native_host` and `needs_browser`. Launch preparation
and final claim bind that distinction to the frozen assignment. Browser routes
also require an owner-approved registered Mac, a Claude account and model,
current unattended-host evidence, advertised execution/browser capabilities,
exact daemon and project mapping, and qualified Chrome, interpreter and launcher
pins. Missing trusted launcher evidence returns a wait before launch. Ordinary
manual runs retain their existing behavior.

The fixed `aeon_browser_capture` tool accepts only URL, desktop/phone viewport
and opaque output identity. A coding worker submits a broker job; it receives no
browser launcher or sandbox override. A capture coordinator receives only that
tool. Built-in browser tools, arbitrary JavaScript, credentials, output paths,
form submission, shell commands and deployment are absent from its inventory.

The broker allows exact configured HTTPS origins, or one separately approved
synthetic loopback fixture origin. Its GET-only reader checks redirects and
every resolved address, then dials the checked IP to prevent DNS rebinding.
Queries, user information, cookies and authorization headers are unavailable.
Requests have a 30-second job deadline, 10-second fetch deadline, four redirects,
64 requests, two page reads and an aggregate 8 MiB response limit. Captures are
PNG, at 1440×900 or 390×844, with an 8 MiB output limit and bounded decode size.
Every job gets a new private browser profile separate from personal accounts.

Executor collaborators must persist a run/output/digest intent before startup,
cap capture admissions, and atomically attach the PNG and owned-exit receipt.
They repeat current owner/target authorization under the final write fence.
Replay returns the same receipt; a pending or uncertain intent waits instead of
launching again. Failed attachment writes and uncertain process cleanup never
produce a success. Cleanup uses the capture process's exact retained ownership
identity; an uncertain exit retains the intent and private profile.

This slice supplies the broker, request/receipt protocol and qualification
seams. No shipped native adapter currently implements the required browser
process and network boundary, and no production receipt store is wired here.
Automatic execution remains off. Coordinator/OPS S26 must implement or select
and qualify the exact native launcher, prove bounded real Chrome desktop/phone
captures and owned tree exits, and attest the final artifacts before a person
can enable a project. Synthetic tests exercise broker/refusal behavior; they
are not native Chrome evidence. Existing machine browser guards are unchanged.
