# Routine review and fix continuation

Accepted completion telemetry records durable continuation demand. A worker
cannot launch its own reviewer or select its own approval. The server executor
requires current routine consent, owner rights and the live project lead's
generation, cadence and admission checks before advancing.

Every review and fix retains the original routine-run budget. Confirmed process
exit and complete trusted usage settlement precede another actor. Unknown usage
retains its hold; replay and restart reuse the same completion receipt rather
than creating another review, charge or queue turn.

Reviews use the existing registry, family policy, exact commit range, no-tools
transport and verdict parser. A changed range, policy, family, effective model
or CI admission closes advancement. The project’s required product taste and
merge gates remain coordinator-owned. An independent `ok` produces an exact-head
pending pipeline handoff, with no merge, deployment or Done authority.

Fixes use the current fix route and keep the previous writer’s account, order
and checkout identity. Changed ownership or missing local process/resource exit
proof refuses continuation. The approved fix-round and shared recovery limits
remain finite. Exhausted attempts create one Decision Desk question. A failed
fix also parks immediately because its artifact has not been verified; its
completion cannot start an immediate retry loop.

Execution remains default-off. Production still needs accepted exact-artifact
runtime, admission and provider-budget bindings plus the separate person-owned
project enablement. Missing capabilities remain explicit waits or launch refusals.
