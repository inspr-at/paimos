# Independent routine evaluation

Every typed outward routine action retains the compiled different-family checkpoint. The coordinator resolves the existing review role from the current model registry, person preferences and project family policy. Switching ordinary cross-family review off does not remove this routine checkpoint. Author and evaluator identity comes from vendor-reported effective models which satisfy their immutable requested pins.

The internal action broker persists a bounded evaluation request before dispatch. It binds the routine run, author run, action, complete typed payload digest, target/revision and current update timestamp, repository head where applicable, context, guardrail policy, family policy, reviewer profile/account and deadline. The author must be the action's recorded non-evaluation attempt, or the main run when no attempt is recorded. Replays reuse a current identical request; an expired request without verified evidence needs fresh evaluation. A verified result remains bound to the unchanged action and policies even after its evaluator deadline or person hold expires. Another evaluator run cannot replace it; only a changed binding reopens evaluation. Existing routine tables hold the request and append-only result receipts. No new endpoint or migration is added.

Results require one explicit structured JSON object containing `request_digest`, `verdict` (`allow`, `needs_person` or `block`) and a bounded `reason`. Missing, ambiguous, unfinished, unverified, same-family, forbidden-family, timed-out or stale evidence keeps the action pending or blocked. Deterministic blocks remain blocks. The fixed evaluator capability is read-only and its admission is deterministic, with a run-bound pre-reserved input/output allowance; it does not recursively evaluate itself or receive outward tools.

A verified needs-person result uses the existing approval source in Decision Desk, with a separate 24-hour expiry from recording the evaluator result. The receipt persists that recording time and must show completion before the two-minute evaluator deadline; a person may decide afterward while the hold remains live. Its narrow permission scope binds the complete evaluation request and does not grant ordinary mutation authority on the node. Only a current person owner or administrator with the necessary permissions may decide it. Consumption rechecks the exact request, target and current person's authority in the final action transaction. Changed heads, payloads, policies, expired person holds and revoked grants cannot reuse approval.

This slice supplies an internal boundary, not an executable evaluator. `AdmitEvaluation` always refuses with `budget_enforcement_unavailable` until S09/S10 supply qualified provider spending enforcement. Recording evidence or resolving a person hold grants no execution, merge or deployment authority. Production wiring, project qualification and person-owned enablement remain separate; automatic execution stays off.
